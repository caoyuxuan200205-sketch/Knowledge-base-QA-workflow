# 博物馆知识工坊

一个轻量的博物馆知识库生产工作流。馆方可以导入现有 QA 表格或普通资料，自动整理为候选问答，再完成审核、修改与导出。

## 已实现

- 批量拖拽导入 `.pdf`、`.xlsx`、`.xls`、`.csv`、`.txt`
- 文本型 PDF 按页提取正文，并在 QA 来源中保留文件名和页码
- 自动识别没有文本层的扫描页，暂不选中并提示需要 OCR
- PDF Worker 作为独立静态资源加载，避免开发环境热更新冲突
- Excel 多工作表识别、启用与停用
- 导入前数据预览和问题列、答案列、名称列映射
- 支持追加到现有知识库或替换现有知识库
- 保存最近导入记录
- 自动识别“问题 / 答案”列并迁移现有 QA
- 普通表格和文本自动生成候选 QA（大模型生成默认开启，本地规则可作兜底）
- 自动划分文物信息、展览内容、馆务服务、参观政策、基建导览等分类
- 搜索、分类筛选、状态筛选
- 单条编辑、标记修改、审核通过、批量通过
- 浏览器本地自动保存
- 导出标准 Excel 和完整 JSON
- 从已审核 QA 生成评测集，并保留来源 QA 与资料来源
- 覆盖标准问答、同义改写、口语表达、要点完整性、抗幻觉边界五类评测维度
- 评测集默认由当前大模型出题（同义改写、口语表达、抗幻觉边界等维度），标准问答基准题直接取自来源 QA；也可切换回本地规则
- 大模型出题参考答案本地回填（模型只产出问题、评分标准、关键词，不重复输出答案），按 6 条 QA/批、3 批并发调用，逐批增量入库、切页可见
- 评测集覆盖率分析、逐条审核编辑，并可导出 Excel 或 JSON

## 评测集生产流程

1. 优先选择“已通过”的 QA 作为标准答案来源。
2. 选择评测维度与出题引擎（默认当前大模型，按 6 条 QA/批、3 批并发调用，参考答案自动取自来源 QA）。
3. 生成与来源 QA 绑定的待审核样本，边生成边入库，检查来源 QA、知识分类和评测维度覆盖率。
4. 审核测试问题、参考答案、评分标准和必含关键词。
5. 导出 Excel 或 JSON，用于模型、提示词或知识库版本的回归测试。

## 本地运行

```bash
npm install
npm run dev
```

浏览器打开终端显示的本地地址，通常为 `http://localhost:3000/`。

## 推荐导入格式

最简单的格式是：

| 问题 | 答案 |
| --- | --- |
| 博物馆几点开放？ | 开放时间请以馆方当日公告为准。 |

也可以导入包含“文物名称、年代、材质、工艺、价值”等字段的普通资料表，或直接导入带文本层的 PDF；系统会根据字段或页面正文生成候选问答。

## 数据说明

当前版本是本地 MVP，数据存储在当前浏览器的 `localStorage` 中，不会自动上传到服务器。正式多人协作时可继续接入数据库、用户权限和模型 API。

## 后续大模型接口

QA 生成与评测集出题均已接入大模型，本地规则仅作为可选兜底：

- QA 生成：导入页默认使用当前大模型生成候选 QA（`lib/qa-model-service.ts`，按 12 条资料/批、3 批并发，逐批增量入库），可切换为本地规则
- 评测集生成：评测页默认使用当前大模型出题（`lib/evaluation-model-service.ts`），其中“标准问答”基准题直接取自来源 QA 原文，不消耗模型额度；其余维度由模型按 6 条 QA/批、3 批并发生成，只产出测试问题、评分标准和必含关键词，参考答案由系统从来源 QA 本地回填
- 模型输出经过字段校验与维度白名单过滤，来源 QA 通过 `sourceQaId` 绑定，超纲维度和短答案的“要点完整性”题会被自动丢弃

普通资料使用本地规则生成候选 QA；已有“问题、答案”列的资料会原样迁移并补充分类和来源。后续接入大模型时，流程保持不变，只替换“生成候选 QA”步骤，并要求模型返回固定字段：

```json
{
  "question": "标准问题",
  "answer": "有资料依据的答案",
  "category": "文物信息",
  "source": "文件名 · 工作表 · 行号",
  "confidence": 0.9
}
```

项目现已包含独立的模型注册表和 OpenAI Chat Completions 兼容适配层：

- 顶部可以快速切换当前模型
- 模型管理页可以新增、复制、停用和删除模型
- 预置 `Deepseek-v4-flash`、`GLM-5.2`
- 支持自定义服务商、模型 ID、接口地址和 Token 上限
- 支持记录工具调用、图片、推理和结构化输出能力
- 模型配置保存在本机浏览器
- API Key 只写入当前会话的 `sessionStorage`，不会进入项目代码和长期存储

当前已经完成：

- 本地服务端安全代理 `/api/llm`
- 模型连接测试
- API Key 会话级存储
- 同服务商模型之间同步 Key
- 导入阶段可选择“本地规则”或“当前大模型”生成候选 QA
- 大模型按批次处理普通表格和文本，并返回带来源行号的结构化 QA
- 已有“问题、答案”列的资料直接迁移，不重复消耗模型额度
- 大模型生成逐批增量入库：每批完成立即写入知识库并同步本机保存，审核页实时可见，可边生成边审核；顶栏显示全局批次进度，切换页面不中断，中途出错不丢已完成批次
- 生成任务进行中会阻止重复发起（按钮禁用 + 导入守卫）

使用时进入“模型管理”，粘贴 API Key 并点击“测试连接”；连接成功后回到资料导入页，将生成引擎切换为当前模型。
