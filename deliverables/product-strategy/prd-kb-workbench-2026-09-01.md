## 0. 现状基线（已实现，不在需求池内）

本章仅陈述事实，用于锚定后续需求的技术起点。**需求池（第 6 章）只放待做项。**

**技术形态**：Next.js（vinext）+ React 19；全部数据存浏览器 `localStorage`（单键 `museum-kb-workflow-v1`，结构 `{ museumName, items, history, evaluationItems, models, activeModelId }`）；本地 `/api/llm` 服务端代理；模型注册表可切换（预置 Deepseek-v4-flash、GLM-5.2，均走微信 Coding Plan，支持自定义 OpenAI 兼容服务商）；API Key 仅存 `sessionStorage`；无服务端数据库。

**已实现能力**：

1. **资料接入**：多文件拖拽。PDF 用 pdfjs 提取文本层，无文本层页面自动识别并标记 `requiresOcr`、默认不选中、提示需 OCR。Excel 多工作表识别与启停、列映射（问题/答案/名称列）、导入前预览。支持 CSV、TXT。
2. **QA 生成**：本地规则 / 大模型双引擎，默认大模型。12 个语义块/批，3 批并发（worker pool）。结构化 JSON 输出。`maxOutputTokens = min(12000, model.maxOutputTokens)`，temperature 0.15。prompt 含防注入声明（资料为不可信输入）。分类白名单 6 类 + 关键词规则兜底。来源留痕到"文件名·页码·行号"。
3. **分类体系**：文物信息 / 展览内容 / 馆务服务 / 参观政策 / 基建导览 / 其他。
4. **审核**：待审核 / 已通过 / 需修改 三态。单条编辑、批量通过、搜索、分类与状态筛选。已处理条目变灰（`opacity-65 saturate-75`）。审核通过/标记修改后自动跳下一条。单条删除带二次确认。
5. **评测集**：从已审核 QA 生成。5 维度（标准问答 / 同义改写 / 口语表达 / 要点完整性 / 抗幻觉边界）。大模型出题 6 条 QA/批 × 3 并发，参考答案本地回填（模型不重抄答案）。标准问答基准题本地生成不耗额度。答案 <35 字跳过"要点完整性"。覆盖率分析。Excel / JSON 导出。
6. **过程管控**：逐批增量入库（每批完成即写 localStorage，边生成边审）。顶栏全局进度徽标（切页可见）。停止按钮（软停止：停止调度新批次，在途最多 3 批跑完即停，保留已入库数据）。防重复发起（`runActiveRef`）。
7. **导出**：QA Excel（sheet 名 `qa_import_template`，列：问题/答案/分类/来源/审核状态/可信度/更新时间）+ JSON（带馆名）。评测集 Excel + JSON。
8. **模型管理**：模型注册表增删改、连接测试、同服务商 Key 同步。

**已知结构性缺口（本 PRD 的需求池即由此展开）**：单馆单库（换馆即覆盖）、sources 不持久化（刷新剩余批次不续跑）、`/api/llm` 未透传上游 `usage`（成本只能估算）、扫描件只能跳过。

## 1. 产品目标

本阶段三个目标，彼此正交，分别对应任务生命周期的**事前、事中、跨任务**三个阶段。

### G1 可预估（事前）
在任务发起**之前**，用户就能拿到产出条数、耗时、成本的可信区间，且表格类与 PDF 类分开给口径。
**目标度量**：预估条数与实际条数的平均绝对百分比误差（MAPE）≤ 20%，在马王堆、湖南博物院、忻州长城博物馆三个已跑通案例上回归校验通过。

### G2 可止损（事中）
任何长任务都能随时叫停，停后已产出不丢，且允许改参数后继续跑剩余部分。
**目标度量**：80 批任务在任意时刻中断后恢复，数据丢失 0 条，从打开页面到恢复运行的操作耗时 ≤ 30 秒。

### G3 可复制（跨任务 / 跨馆）
新增一个同类型馆的边际配置成本趋近于零，前一馆的语料、QA、评测集不与新馆互相污染。
**目标度量**：从模板新建一个同类型馆并完成首次试跑 ≤ 15 分钟，需手工填写的配置项 ≤ 3 处。

**北极星指标（由数析提出，本阶段先完成可观测性建设）**：
EDR（有效交付速率）= 通过审核且去重的 QA 条数 ÷ 端到端生产耗时（小时）。
当前**算不出来** —— 分母缺时间戳、分子缺去重标记。补齐 `batch_end` 与 `review_action` 两个埋点即可开算（见 P2-2）。

**本阶段不做的事**：不追求提升单条 QA 的内容质量（见 8. Non-goals 与第 3 章 H1 风险）。

## 2. 用户故事

### US-1（R1 知识库生产负责人）换馆复用
> 我是知识库生产负责人。刚交付完马王堆的知识库，现在要接湖南博物院。我希望新建湖南博物院时，马王堆的 261 条 QA 还完整地躺在马王堆的库里，湖南博物院是一张白纸，而不是把马王堆的数据覆盖掉。我还希望上馆调好的生成参数（每实体问数、分类白名单、导出机构 ID）能存成模板，新馆一键套用，只改馆名和几个差异项。

**当前状态**：做不到。localStorage 单键单馆，换馆即覆盖。馆级配置无任何持久化载体。

### US-2（R1）报价前预估
> 甲方问"这套知识库做下来多少钱、多久、多少条"。我不想再拍脑袋。我希望把资料拖进去、参数配好之后，界面直接告诉我：这批资料大概能出多少条 QA、要跑多少批、大概多少分钟、大概多少钱。表格类的资料我要一个确定的数，PDF 类的我接受一个区间，但区间不能有数量级的偏差。

**当前状态**：完全没有预估。只能跑完才知道。

### US-3（R1 / R2）大任务止损
> 我发起了忻州长城博物馆大纲 PDF，80 个批次。跑到第 10 批我发现方向不对 —— 模型在生成大量无价值的套话。我要能立刻停，停完前面 10 批产出的 QA 还在，我改成更严的 prompt 或换个模型，接着把剩下 70 批跑完，而不是从头再来。

**当前状态**：停止按钮（软停止）已实现，已入库批次保留，但**没有"改参数续跑"入口**，只能重新导入重跑，靠问句去重兜底。

### US-4（R2 审核执行人）审核流水线
> 我要在两小时内过完 1000 条待审 QA。我需要用键盘走完：J 下一条、A 通过、R 标记修改、D 删除，不用摸鼠标。我不小心误删了一条要能 Ctrl+Z 撤回来。对同一批明显有问题的条目，我要能框选一片然后一次性处理掉，而不是点 50 次。

**当前状态**：只有单条操作 + 自动跳下一条、批量通过（现有"批量通过"为按当前筛选全量通过，无多选）。无撤销、无快捷键、无按选区批量。

> 注：R2 当前由 R1 兼任，尚未独立化（见第 3 章）。US-4 的痛点已真实存在，但**不涉及**分配、协作、仲裁。

### US-5（R1）交付前质量自检
> 交付前我想快速扫一遍这批 QA 有没有硬伤 —— 空答案、同一个问题问了八遍、答案长到离谱、某个分类占了 90%。我不指望工具替我判断内容对不对，但机器能查的规则先帮我查完，我只处理机器报出来的那部分。

**当前状态**：零校验。全部靠人眼过。这是本阶段最大的隐性风险敞口（H1）。

### US-6（R1）成本对账
> 我这个月跑了多少 token、花了多少钱、单条 QA 成本多少，我要能直接从系统里读出来，而不是拿估算系数去反推。

**当前状态**：`/api/llm` 代理未透传上游 `usage`（已核实代码），成本只能按估算系数推算。

## 3. 用户研究洞察（来源：瑞思）

### 3.1 角色定义

| 角色 | 定义 | 验证状态 |
|---|---|---|
| **R1 知识库生产负责人** | 曹宇轩本人。对交付结果负责，需要向甲方报价、排期、交付 | **唯一已验证角色** |
| **R2 审核执行人** | 当前由 R1 兼任，尚未独立化 | 未独立验证 |

**R1 的心智模型**：有 AI 产品背景，能理解 token / 并发 / 批次等工程概念。因此他提出的需求形态通常是**"给我旋钮"**（参数化、可配置、可观测），而非"帮我自动搞定"。这一点直接决定了本 PRD 需求池的形态 —— 大量需求是"暴露可控参数 + 给出可观测读数"，而非"提升自动化程度"。

**R2 的空白含义**：10 条反馈中**零条**涉及协作、任务分配、多人仲裁、进度交接。所有痛点都是**单人长时间劳动**的痛点。这是 8. Non-goals 中"多人协作与权限审批"被排除的直接依据。

### 3.2 三条 P0 洞察

**洞察 ① 长任务黑盒化导致掌控感丧失**
停止按钮在用户心智中的真实语义不是"我不跑了"，而是**"我看出方向不对，立刻止损重配"**。
→ **设计推论**：停止不是一个终止态，而是一个**中转态**。停止后的界面必须同时提供"保留已产出"和"改参数续跑"两个能力，否则停止按钮只完成了一半语义。
→ 对应需求：P0-3。

**洞察 ② 产出量与耗时不可预估导致无法报价**
"表格一行 ≈ 一个实体"是可数的；"PDF 由模型识别"是不可数的。这是**两种本质不同的不确定性**，不能用同一套预估口径糊过去。
→ **设计推论**：表格类给**确定性数值**（行数 × 每实体问数），PDF 类给**区间估计**（先轻量预扫，再给区间）。
→ 对应需求：P0-4。

**洞察 ③ 任务不可恢复导致沉没成本恐惧**
80 批跑到 60 批刷新全丢，用户被迫**不敢离开页面**。这不只是体验问题 —— 它直接**限制了单次任务的规模上限**，用户会自我约束成"只敢跑能盯完的量"。
→ **设计推论**：断点续跑不只是补体验，它是**解除产能天花板**的前提。
→ 对应需求：P0-2。

### 3.3 最大风险：H1

> **H1**：用户 10 条反馈中**零条**抱怨 QA 内容质量。这更可能是"关注点还在跑通流程、质量靠人工兜底"，而非质量已达标。质量问题可能在甲方验收期集中爆发，**返工成本最高**。

**对冲策略**：不追求提升模型生成质量（成本高、见效慢、难验收），而是用**低成本的机器校验**把人工兜底的范围缩小：
- **抽样预览**：全量发起前先试跑 1 批，看 12 条样例，方向不对就立刻改参数，止损成本从"80 批"降到"1 批"。
- **批量规则校验**：机器能查的规则（空答案、重复问法、超长、维度配比异常）先查完，人工只处理机器报出的部分。

→ 对应需求：P1-4。**这是本 PRD 中成本收益比最高的单项需求，建议不要因排期压力被砍。**

## 4. 竞品对比（来源：竞析）

### 4.1 生态位判定：我们不是 RAG 平台的竞品，是上游

Dify / RAGFlow / 腾讯 LKE / 千帆 AppBuilder / FastGPT / 扣子 —— **无一原生提供"自动生成 QA 对"**。这些平台语境下的 "Q&A" 指的是**按问答格式切分已有 FAQ 文档**，不是从原始资料**生成**新问答对。

- 它们的切片服务于**检索**；我们的 QA 对服务于**交付与评测**。
- 因此我们是 RAG 平台的**上游供给方**，切入检索即同质化（见 8. Non-goals）。

### 4.2 真正的对手是 EasyDataset，不是 Dify

EasyDataset 已跑通完整链路：**文档 → 分块 → 批量生成 QA → CoT 答案 → 标签树 → 内置评测（v1.7.0 含判断/单选/多选/简答/开放题 + Judge 自动打分 + 人工盲测 Arena）→ 导出 Alpaca / ShareGPT / JSON**，本地运行、模型可切。

**它缺的正是我们有的**：

| 能力 | EasyDataset | 我们 |
|---|---|---|
| 多馆隔离 | 无 | P0-1 在建 |
| 来源留痕颗粒度 | 无 | 已有（文件名·页码·行号） |
| 面向下游的 Excel 交付 | 无（只有训练格式） | 已有（`qa_import_template`） |

**威胁判定**：EasyDataset 若补上"工作空间隔离 + Excel 导出 + 来源留痕"，即与我们正面重合。**威胁等级：高**。
其他威胁：Dify / RAGFlow 若上线"知识库生成 QA 对"节点（高）；腾讯 LKE 向下游延伸（中高）。
**判断窗口期：6–12 个月。**

### 4.3 合规锚点：T/SAIAS 063-2026

团体标准 **T/SAIAS 063-2026《文物大模型应用评测指标体系》**（2026-07-13 发布、2026-07-14 实施，上海人工智能行业协会归口，上海博物馆、上海市历史博物馆、上海大学、复旦大学、商汤等起草）给出**四大维度三级指标与五级分级**，且**安全维度不达标可直接判定停用**。

**战略含义**：我们的 5 维度目前是"经验设计"。对标团标后，评测集可从"我们自己觉得合理"升级为**投标材料级的合规背书**。这是从"工具"跃迁到"可投标方案"的关键一步。
→ 对应需求：P1-1。

### 4.4 硬伤：OCR

RAGFlow DeepDoc、腾讯 LKE（OCR + MLLM，支持 26 类文档）已把扫描件解析做成**标配**。而博物馆资料中扫描件是**常态**。
我们目前的处理是：识别到无文本层 → 标记 `requiresOcr` → 默认不选中 → 跳过。
**这是当前最明显的能力缺口**，直接影响可接入资料的覆盖面。
→ 对应需求：P1-2。

### 4.5 价值论据（可直接用于对外材料）

> 北大 / 北交大 VaseMuseum 实测（2026-07）：给博物馆问答 AI 加**不受控联网搜索**后，纯视觉题准确率从 **44% 跌到 20%**，幻觉率从 **54% 飙到 79%**。

这是"**资料可控 + 来源留痕**"这一产品价值最硬的外部论据 —— 联网检索非但没有补上知识缺口，反而显著放大了幻觉。建议在投标材料与产品对外介绍中作为核心论据引用。

## 5. 数据依据（来源：数析）

> **口径声明**：本章凡标注"（估算）"的数字均为基于已跑通案例反推的估算值，**不是实测值**。未标注的为实测统计值。

### 5.1 已跑通案例的实测基线

| 案例 | 输入 | 产出 | 答案长度 p50 | 重复情况 |
|---|---|---|---|---|
| **A 马王堆** | 84 件文物表格 | **261 条 QA**（≈3.1 条/件） | **150 字** | **0 重复** |
| **B 湖南博物院** | 综合资料 | **106 条 QA** | **74 字** | **8 条重复（7.5%）** |
| **C 忻州长城博物馆** | 大纲 PDF | 80 个批次的大任务 | — | — |

**案例 B 维度分布**（实测）：参观政策 49% / 其他 16% / 展览内容 13% / 基建导览 13% / 馆务服务 4% / 文物信息 4%。

### 5.2 单位经济性（估算）

| 指标 | 数值 | 口径 |
|---|---|---|
| 单条 QA 全链路 token | **≈ 255**（估算） | 案例 A 258 / 案例 B 252，两案独立收敛 |
| 单条评测题 token | **≈ 170**（估算） | 仅模型生成部分 |
| 评测集放大倍数 | **≈ 5×**（估算） | 案例 A ≈ 1302 题、案例 B ≈ 514 题 |
| 80 批大任务耗时 | **≈ 71 分钟**（估算），区间 40–100 | 忻州任务 |
| 维度有效数 | **3.3**（名义 6） | 均衡度 55%，HHI = 0.3027 |

**优化收益（估算）**：
- 参考答案本地回填（模型不重抄答案）：相对朴素方案**省 39%**
- 叠加"标准问答"基准题本地生成后，单条 QA 全 5 维合计**省 51%**

### 5.3 成本换算（示例口径，需按实际模型单价复核）

| 项目 | 输出 token | 输入 token |
|---|---|---|
| 千条 QA | ≈ 140k（估算） | ≈ 118k（估算） |
| 千条 QA 的全 5 维评测集 | ≈ 361k（估算） | ≈ 320k（估算） |

按**输出 ¥8/百万、输入 ¥2/百万**的示例单价：千条 QA 及配套全 5 维评测集合计 **≈ ¥4.9（估算）**。
⚠️ 此单价为示例口径，Deepseek-v4-flash / GLM-5.2 经微信 Coding Plan 的实际结算方式待确认（见第 10 章 Q4）。

### 5.4 "卡在 0/80" 的根因

首批输出逼近 12000 token 上限，**需约 240 秒（估算）**；而增量入库是"每批完成才写"，导致**前约 4 分钟进度恒为 0**。

> **这不是失败，是反馈缺失。**
> ⚠️ **但存在一处代码级冲突需优先裁决**：`/api/llm` 代理的 upstream fetch 带有 `AbortSignal.timeout(120000)`（120 秒）。若首批确需约 240 秒（估算），则该请求会在 120 秒时被代理主动超时中断。此问题**必须在 P0-3 开工前确认**（见第 10 章 Q1）。

### 5.5 重要判读：哪些指标能用来考核模型

| 指标类型 | 具体指标 | 用途 |
|---|---|---|
| **输入语料体检指标** | 维度分布（有效数 3.3）、答案长度分布（p50） | 反映**语料配比**，不该用来考核模型 |
| **模型质量指标** | 重复率（A 0% / B 7.5%）、超生成率 | 反映**模型表现**，才是考核对象 |

**关键结论**：省博"文物信息仅 4%"是**语料配比问题**，不是模型问题。把它当成模型优化目标会走错方向。同理，P1-4 的"维度配比异常"校验规则，其定位是**语料体检告警**，不是质量评分。

#### P0-1 多馆隔离 + 馆配置模板

**现状**：`localStorage` 单键 `museum-kb-workflow-v1`，结构 `{ museumName, items, history, evaluationItems, models, activeModelId }`。换馆 = 覆盖。

**方案要点**：
- 键名命名空间化：馆数据 `kbw:v1:museum:<museumId>`；馆索引 `kbw:v1:index`；模型注册表 `kbw:v1:models`（**跨馆共享**，模型是用户级资产不是馆级资产）。
- 一次性迁移：检测到旧键存在时自动迁移为首个馆，全量保留 `items` / `evaluationItems` / `history`，迁移后面提示并保留旧键备份 7 天。
- 馆配置模板：JSON 导入导出，含 schema 版本号，导入时校验。

**验收标准**：
- **AC-1.1** Given A 馆已有 261 条 QA，When 新建 B 馆并生成 50 条 QA，Then 切回 A 馆其 QA 条数仍为 261 且内容与离开前逐条一致，B 馆为独立库。
- **AC-1.2** 顶栏馆切换器列出全部馆，每项显示「馆名 / QA 条数 / 评测题数 / 最近更新时间」，按最近更新时间倒序。
- **AC-1.3** 当前馆 ID 体现在 URL（`?museum=<id>`），刷新后仍停留在同一馆，链接可直接分享复现。
- **AC-1.4** 删除馆需二次确认并手动输入馆名，确认后释放该馆 storage key；删除不可撤销，确认框内明示。
- **AC-1.5** 模型注册表与 API Key 跨馆共享，切换馆后模型列表、当前选中模型、连接状态均保持不变。
- **AC-1.6** 「从模板创建馆」：上传模板 JSON 后，新馆继承其中全部配置项（馆名除外）；模板 schema 版本不兼容时明确报错而非静默使用默认值；模板导出为 `.json` 文件。
- **AC-1.7**（迁移）Given 本地存在旧键 `museum-kb-workflow-v1`，When 首次加载新版本，Then 自动生成名为原 `museumName` 的馆，其 QA 条数、评测题数、导入历史与升级前完全一致，差异为 0 条。

#### P0-2 任务持久化与断点续跑

**现状**：`generationRun` 为内存状态，`sources` 未持久化。刷新后已完成批次已落盘不丢，但剩余批次不续跑。

**方案要点**：持久化任务记录 `kbw:v1:task:<museumId>`，结构含 `type`（qa/eval）、`status`、`sources`（序列化）、`batches[]`（`{ index, status: pending/running/done/failed, itemsCount }`）、`cursor`、`config`、`startedAt`、`endedAt`。

**验收标准**：
- **AC-2.1** Given 80 批任务已完成 60 批，When 刷新页面，Then 顶部出现恢复横幅「上次有未完成的任务 · QA 生成 · 已完成 60/80 批 · 已产出 N 条 · 是否继续？」，点击继续后从第 61 批接着跑。
- **AC-2.2** 断点续跑完成后，总产出条数与一次性跑完的结果**差异为 0 条**（允许问句去重导致的自然差异，但不允许批次丢失）。
- **AC-2.3** 关闭浏览器标签页后重新打开（同浏览器、同 origin），恢复横幅同样出现且可续跑。
- **AC-2.4** 任务记录含 `startedAt` / `endedAt`，任务历史列表展示最近 20 条，含类型、批次数、产出条数、耗时、结束原因（完成 / 停止 / 失败）。
- **AC-2.5** 当单任务 `sources` 序列化后超过 4 MB 时，明确提示「资料过大，断点续跑不可用，请先拆分资料」，并说明 localStorage 5MB 配额限制；此时不静默降级。
- **AC-2.6** 续跑失败时按原因分别提示（模型 Key 失效 / 接口不可达 / 配额超限），不吞异常，不静默回到空状态。

#### P0-3 过程透明与可止损

**验收标准**：
- **AC-3.1** 任务发起后 **≤ 3 秒**内，进度区从「准备中」变为「已发出第 1/N 批请求」，首批结果返回前不得出现长时间静止的 `0/N`。
- **AC-3.2** 顶栏进度徽标实时展示五项语义：`任务类型 · 已完成 X/N 批 · 已产出 M 条 · 在途 K 批 · 预计剩余 T 分钟`；每批完成后 **≤ 1 秒**内更新。
- **AC-3.3** 预计剩余时间 =（已完成批次平均耗时 × 剩余批次数 ÷ 并发度），每完成一批刷新一次；已完成批次数 < 3 时显示「估算中」，不给具体数字。
- **AC-3.4** 停止后展示中转面板「已停止 · 保留 M 条 · 剩余 N 批」，提供两个按钮：「改参数续跑」与「放弃剩余批次」。
- **AC-3.5** 「改参数续跑」允许修改：模型、每实体问数、分类白名单、并发度；续跑只处理未完成批次，已产出条目不重新生成；改参数后新配置仅作用于剩余批次并在任务记录中留痕。
- **AC-3.6** 单批失败（超时 / 接口错误）不阻塞后续批次：该批标记 `failed`，任务结束后汇总「N 个批次失败」，提供「一键重试失败批次」，重试只跑失败批次。

> **前置依赖**：AC-3.6 依赖第 10 章 Q1 的裁决结果（代理 120 秒超时 vs 首批约 240 秒估算）。若确认为超时所致，需同步调整代理超时或批次大小。

#### P0-4 产能预估

**方案要点**：表格类与 PDF 类**分开给口径**，对应第 3 章洞察 ② 中"两种本质不同的不确定性"。

**验收标准**：
- **AC-4.1** 在导入中心完成文件选择并配置后、点击「生成」**之前**，展示预估卡片：预计 QA 条数 / 批次数 / 预计耗时区间 / 预计 token 与费用（费用使用当前模型单价，卡片上标注「估算」）。
- **AC-4.2**（表格类）条数预估 = 选中有效行数 × 每实体问数，在同一语料上实测校验，误差 **≤ ±10%**。
- **AC-4.3**（PDF 类）预扫 **≤ 5 秒**给出条数区间 `[下限, 上限]`；以马王堆、湖南博物院、忻州三个案例回归校验，实测条数落在区间内的比例 **≥ 80%**。
- **AC-4.4** 每实体问数在预估卡片上可直接修改（1–5，PDF 类默认 3），修改后条数、批次、耗时、费用预估**实时重算**，无需重新预扫。
- **AC-4.5** 任务结束时展示「预估 vs 实际」对比（条数 / 耗时 / 成本三项）；当条数或耗时偏差 **> 50%** 时高亮提示，用于校准后续预估参数。

#### P1-3 成本统计

**现状**：`/api/llm` 代理响应**未透传**上游 `usage` 字段（已核实 `app/api/llm/route.ts`），成本只能按估算系数反推。

**验收标准**：
- **AC-7.1** `/api/llm` 代理响应透传上游 `usage` 的 `prompt_tokens` / `completion_tokens` / `total_tokens` 三个字段，前端按批次累计。
- **AC-7.2** 任务级成本卡显示：输入 token 总数、输出 token 总数、按当前模型单价计算的费用（输入与输出单价分开计算）。
- **AC-7.3** 单价可在模型注册表中编辑（元/百万 token，输入/输出分列）；预置 Deepseek-v4-flash / GLM-5.2 的占位单价并在界面标注「待复核」。
- **AC-7.4** 馆级累计成本看板：该馆 QA 生产累计花费、评测集累计花费、单条 QA 平均成本。
- **AC-7.5** 当上游未返回 `usage` 时显示「—」并计入「未计量」计数，**不得按 0 计入**累计成本。
- **AC-7.6** 成本数据随任务记录持久化，断点续跑后累计值不丢失。

#### P1-4 质量前置校验（对冲 H1 风险）

**验收标准**：
- **AC-8.1** **抽样预览**：生成前可发起「试跑 1 批」，展示该批 12 条样例 QA，提供「确认全量发起」与「改参数重跑」两个出口；试跑产出的 QA 默认不入库，可勾选保留；试跑的耗时与 token 计入成本统计。
- **AC-8.2** **批量规则校验**：任务结束后自动执行 5 条规则并输出校验报告 —— ① 空答案或空问题 ② 答案过短（< 15 字）③ 问句归一化后重复 ④ 答案超长（> 800 字）⑤ 单维度占比 > 60%。
- **AC-8.3** 校验报告作为审核页的「质检」标签页呈现，每条命中项可一键跳转到对应 QA 条目，支持按规则类型筛选与批量删除。
- **AC-8.4** 上述 5 条规则的阈值可在馆配置中调整，调整后重跑校验即刻生效（无需重新生成 QA）。
- **AC-8.5** 校验为**纯本地计算**，不调用模型；1000 条 QA 量级下校验耗时 **≤ 2 秒**。
- **AC-8.6** 校验报告明确标注：维度配比异常（规则⑤）属于**语料体检告警**，不是模型质量评分（依据第 5.5 节判读）。

- **AC-9.3** **批量删除**：交互同 AC-9.2，确认框显示将删除条数，并明示「超出撤销窗口后不可恢复」。

## 8. Non-goals

以下事项**明确不在本阶段范围内**，并说明排除理由。

### 8.1 多人协作与权限审批
**不做**：任务分配、多人同时审核、审核仲裁、角色权限、进度交接、评论批注。
**理由**：用户研究中 10 条反馈**零条**涉及协作。R2（审核执行人）当前由 R1 兼任，尚未独立化，全部痛点都是单人长时间劳动的痛点。当前业务形态是"一个业务方 + 一个运营"，**不是标注工厂**。在零协作诉求的前提下做协作系统，是典型的过度设计。
**复评触发条件**：出现第二个独立的审核执行人角色，或单馆 QA 量超过单人可审核上限。

### 8.2 向量检索与对话应用
**不做**：切片、向量库、embedding、检索、RAG 问答、对话界面。
**理由**：这是 Dify / RAGFlow / 腾讯 LKE / 千帆 / FastGPT / 扣子的地盘，切入即同质化，且会稀释"QA 对资产 + 评测集"这一独特定位。我们是 RAG 平台的**上游供给方**，不是替代品（见 4.1）。
**例外**：若下游客户明确要求"生成完直接能问答"，应作为**独立产品**评估，而非在本工作台内叠加。

### 8.3 模型精调
**不做**：fine-tuning、LoRA、训练数据导出为训练格式（Alpaca / ShareGPT）。
**理由**：我们生产 QA 资产，不训模型。EasyDataset 主打训练数据导出，我们主打 Excel 交付与评测集 —— 这是两者的定位分野，不该被模糊。
**边界**：导出的 QA 数据**可以被他人**用于训练，我们只是不提供面向训练的导出格式与配套工具。

### 8.4 在线协同编辑与单条富文本编辑
**不做**：多人实时协同、富文本编辑器（加粗/图片/表格）、版本对比与合并。
**理由**：QA 对的核心价值在于**结构化与可批量处理**。引入富文本会破坏导出的结构化，且与"批量操作 + 快捷键"的高效审核路径冲突。单条编辑维持现有纯文本输入即可（已实现）。

### 8.5 本阶段不做的其他事项
- **分类体系扩展**（综合概况 / 应急情况 / 推荐规划）：案例 B 中 16% 落入「其他」提示现有 6 类覆盖不足，但样本量仅 2 个馆，不足以定论。已记入停车场，待多馆数据积累后再评估。
- **评测集 Judge 自动打分**：依赖服务端与额外的模型调用成本，本阶段只做规则校验（P1-4），不做模型打分。
- **服务端化与账号体系**：本阶段维持 localStorage + 浏览器端形态。服务端化是架构级变更，需在容量瓶颈显性化后再评估（见第 10 章 Q6）。

## 10. 待确认问题

以下问题均为**真正开放**的决策点，需项目负责人或外部信息才能回答。

### Q1（阻塞 P0-3，最高优先级）代理超时与首批耗时的冲突
`/api/llm` 代理的 upstream fetch 带有 `AbortSignal.timeout(120000)`（**120 秒**，已核实 `app/api/llm/route.ts`）。而数析估算首个批次在逼近 12000 token 上限时需**约 240 秒**（估算）。
→ 若估算成立，首批请求会在 120 秒被代理主动中断。需要裁决：**提高代理超时上限**（用户需等待更久），还是**缩小批次规模**（12 块/批 → 更小，批次数增加）？
→ 该裁决直接影响 P0-3 中"单批失败重试"的设计（AC-3.6），需在 P0-3 开工前定。

### Q2（阻塞 P1-2）OCR 供应商选型
接哪家 OCR？候选：腾讯云 OCR / 百度智能云 / 其他。
博物馆扫描件有三个特殊难点：**繁体字、竖排排版、印章与底纹干扰**。需选定 2–3 家，用真实博物馆扫描件实测准确率后再定。此项还涉及采购与结算，非纯技术问题。

### Q3（阻塞 P1-1）团标全文获取
T/SAIAS 063-2026《文物大模型应用评测指标体系》的**全文获取渠道与时间**？本 PRD 目前掌握的信息仅为：四大维度三级指标与五级分级、安全维度不达标直接判定停用。**四大维度的具体名称尚未核实**，因此 P1-1 的映射表（AC-5.1 / AC-5.3）只能等原文到手后才能定稿。建议立即启动。

### Q4（影响 P1-3 与全部成本展示）模型实际结算单价
预置的 Deepseek-v4-flash / GLM-5.2 经**微信 Coding Plan** 调用时，实际结算方式是什么？是否按 token 计费？若为包月额度，则 P1-3 的"费用"展示应改为"额度消耗"而非金额。第 5.3 节的 ¥4.9/千条 QA 为**示例口径的估算值**，不可直接对外引用。

### Q5（阻塞 P2-3）下游导入模板的确切规格
精卫后台导入模板的**确切字段列表与机构 ID 来源**？机构 ID 由谁分配？需提供模板样例文件后 AC-12.3 才可验收。

### Q6（架构级，影响面最大）localStorage 容量天花板
localStorage 单 origin 配额约 **5 MB**。单馆 QA 上限大约多少条？（按当前结构粗估，量级在数千条，但需实测。）超过后的降级方案是什么？
候选：① 迁移 IndexedDB（架构改造，成本高但一劳永逸）② 导出后归档清理（成本低，但割裂）③ 服务端化（见 8.5，架构级变更）。
→ **这是本产品最大的架构级不确定性**。若不做处理，多馆复用（G3）会在馆数增长后撞墙 —— P0-1 解决的是"隔离"，不解决"容量"。建议在 M1 期间做一次容量实测，为 M3 之后的路线提供依据。
