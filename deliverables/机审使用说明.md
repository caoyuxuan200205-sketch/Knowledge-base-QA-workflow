# QA 机审（简版结论）

## 使用

1. 在模型配置页为“QA 审核”选择一个已启用、已填写 API Key 的模型。建议与 QA 生成模型不同。
2. 进入 QA 审核页，按分类、人工状态或机审状态筛选。
3. 点击“开始机审”，在“上传审核依据”中选择 PDF、Word（.docx）或 TXT 原始资料，可多选，每个文件最多 20 MB。已上传文件可勾选或移除，同名文件成功上传后替换旧版本。
4. 查看文件文字预览和 QA 的依据匹配预览。系统按问题检索原文，并保留相关片段附近的上下文；PDF 标注页码，Word 和 TXT 标注段落。旧版 .doc 请另存为 .docx，扫描页需先 OCR。
5. 确认本次数量后才会发起 API 请求。默认范围为当前筛选内、人工待审核且未机审/过期/失败/停止的 QA；重新关联的依据发生变化时，已完成的待审核条目也可重新机审。不选新文件时沿用 QA 已有关联片段。
6. 默认同时审核 6 条。点击右侧“查看机审意见”，查看简短结论；发现事实问题时附最多两条已核对的原文引用，下面可查看实际送审片段。也可对当前条目单独重审。
7. 新机审不生成六维报告和完整修改稿。旧版详细结果仍可查看，已有建议稿仍可人工采用；原问题与答案会留存，采用后需重新审核。

结论为“未发现明显问题 / 建议修改 / 依据不足”。单次输出额度从 6,000 降至最多 1,200 tokens（同时受模型配置上限约束），保留一定余量供模型完成最终答复；实际速度取决于模型响应和服务商限流。

顶部可随时停止机审，已完成记录保留。生成和机审共享任务锁，不会同时自动运行。刷新后不会自动续跑；中断记录转为可重试。

## 判断边界

- 机审结论不修改人工“待审核 / 已通过 / 需修改”状态，不自动删除内容。
- 新生成的 QA 保存解析原文片段及来源位置。生成模型的引用行号须在实际输入范围内；无效引用剔除并标记依据不完整。
- 历史 QA 没有原文时不从文件名猜测，也不联网补证据，只能检查表达。
- 直接导入的 QA 行不是独立事实依据。仅有这种依据时标为依据不足。
- 事实问题可附最多两条简短引文，系统核对引用 ID 和引文是否真实存在于送审的独立原文中，出处由系统回填。无效引用隐藏并标为“依据不足”；纯表达问题可不引用。
- 检索按中文词片段与英文关键词匹配，并参考来源文件名和相邻上下文，不使用答案相似度单独证明事实。未找到相关原文不代表答案错误，会标为“依据不足”；片段相似也不等于事实已验证，仍由模型核对覆盖范围。
- 相关 PDF 存在未提取的页面时提示人工核查。Word 提取正文和表格文字，图片不做 OCR。
- 原文片段单条最多保存 16,000 字符，超限明确标记截断；机审请求按模型上下文上限进一步控制输入，截断时降为依据不足。
- 结论“未发现明显问题”仅限提供资料范围，仍需要人工判断；没有数值可信度评分。
- 修改问题、答案、分类、来源或依据会令旧结果过期。审核期间产生的迟到结果不能覆盖已修改的 QA。
- 失败是技术状态，不等于内容不合格。429 限流或 503 暂不可用最多自动重试一次，重试也占用现有的 6 个并发名额。遵守服务端 Retry-After；未指定时等待 1.5 秒，要求等待超过 30 秒则标记失败、留待手动重试。停止时立即取消等待。

## 保存与验证

上传资料的文字和文件选择保存在当前浏览器的 IndexedDB 中，不保存原始文件二进制；匹配后的片段、机审记录和采用建议前的原稿沿用 QA 工作区保存。移除上传资料不删除历史 QA 已关联的片段。确认机审后仅向所选模型发送相关原文片段和 QA。

资料本机保存失败时显示提示，当前页面仍可使用。QA 工作区存储空间不足时，请导出 JSON 备份，勿刷新页面；JSON 包含 QA 的已关联依据与结果。普通 Excel 仍沿用知识库导入列。

API Key 继续仅保存在会话中，不写入机审记录。测试使用模拟 API，未调用公司真实模型；模型的实际判断质量需用馆方样例人工对照验证。
